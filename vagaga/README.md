# vagaga

Vue 3 + Tauri 2 桌面工程。

## 构建和运行

改完代码后，双击本目录的 `build-vagaga.cmd`。构建结束后窗口会显示 EXE 的位置或错误信息。
如果正式版 vagaga 正在运行，先保存制作内容并关闭它。

首次在新机器构建时，在本目录运行 `pnpm install --frozen-lockfile` 安装前端依赖。
也可以在终端执行同一个构建：

```powershell
pnpm build:desktop
```

此命令构建前端和正式版桌面程序，编译缓存及 EXE 均位于本工程内。
构建脚本临时指定本工程的 Cargo 输出目录，结束后恢复调用环境；不会复制到其他盘符或软件目录。

统一使用的正式版入口：

```text
src-tauri\target\release\vagaga.exe
```

`dist/` 是前端静态资源目录，不是桌面 EXE 的发布目录。
`src-tauri/target/debug/` 是运行 `pnpm tauri dev` 等开发命令时的调试产物。
需要安装包时，可执行 `pnpm tauri build`，默认生成在 `src-tauri/target/release/bundle/`。

历史上的 `D:\Software\qianfan-paidan`、`E:\Software\qianfan-paidan` 和
`E:\Software\qianfan-target` 不作为本工程的构建或运行入口。
旧启动脚本包含对 E 盘 EXE 的回退路径，后续请直接使用上述工程内的正式版入口。

程序只使用 EXE 同目录的 `data/`，其中包含订单、配置及缓存。
没有此目录时会创建空白本地库；不会导入旧 AppData，也不会在写入失败时回退到其他位置。
程序目录不可写时启动报错，需要将程序放到可写目录。
单独复制 EXE 到新目录可创建独立环境；复制 EXE 及其 `data/` 则保留该环境的现有订单和配置。
请保留需要的旧数据，不要直接删除带有 `data/` 的旧目录。

## 共享存储

在「设置 → 共享存储」选择标签页。「对象存储」提供七牛 Kodo 和 MinIO，「私有化存储」提供 WebDAV 和 SMB。切换标签页和存储类型可以查看和测试相应配置。
MinIO、WebDAV 和 SMB 可以用「保存配置」提前保存连接信息。已有服务在运行时，
为其他服务保存配置会保留当前存储和轮询间隔。点击「保存并启用」即可切换当前存储。
客服机与制作机应填相同的存储位置。

- MinIO 使用已有的 S3 兼容端点、Bucket 和访问密钥。已有 MinIO 配置可以继续使用。
- WebDAV 填写服务地址、相对同步目录和登录信息。目录留空时使用服务地址对应的根目录。
- SMB 填写服务器、共享名、相对同步目录和登录信息。目录留空时使用共享根目录。

「立即同步」会尝试上传待处理素材并拉取云端更新。启用 WebDAV 或 SMB 后，
可以用「补传历史素材」上传存储端缺少清单的历史订单素材。
客户端直连时，MySQL 仍单独同步订单信息和导出的成品。已绑定七牛的数据目录需要沿用七牛配置，
使用其他存储时请使用独立的数据目录。

## 七牛同步

七牛私有空间存原图与成品。Go API 管理设备权限、文件凭证和订单版本，
MySQL 只保存订单、文件编号和校验信息。两端各自在 `data/` 中保存工作所需的文件。

### 服务端准备

1. 准备独立的排单 MySQL 数据库和可通过 HTTPS 访问的七牛私有 Bucket。
   向七牛控制台确认空间所属区域的上传端点，以及绑定该空间的下载域名。
2. 按仓库根目录 `.env.example` 的 `PAIDAN_*` 变量配置 Go 服务进程。
   七牛 AK/SK 留在服务器。应用数据库账号应具有新表所需的查询、写入权限，
   数据库迁移使用有 DDL 权限的账号。
3. 在 `server/` 中为排单数据库执行迁移。迁移进程的
   `PAIDAN_MYSQL_DSN` 指向本次要迁移的库。

   ```powershell
   go run ./cmd/migrate -target vagaga -command up
   ```

4. 在 `PAIDAN_DEVICES_JSON` 中配置每台设备的 `deviceId`、`workspaceId`、
   `role` 和 `tokenSha256`。每台机器使用不同的随机设备令牌，
   服务器登记其 SHA-256 十六进制摘要，两地机器使用相同的业务空间 ID。
   `customer` 为客服，`production` 为制作，`both` 兼具两种权限。
5. 启动 Go 服务并开启 `PAIDAN_ENABLED`。使用 HTTPS API 地址。
   若通过容器启动，需要显式向 Go 进程传入这些变量。
   桌面端「测试连接」会核验设备权限和排单数据库是否就绪。

### 两端接入和验证

1. 在每台 EXE 的「设置 → 共享存储 → 对象存储」选择「七牛 Kodo」，输入 API 地址与该设备的令牌，
   测试连接、保存并重启。工作模式由设备授权决定。
2. 客服机首次升级后刷新或重新打开千帆工作台，加载新版排单脚本。
   用一张测试原图确认排单，客服端显示先落盘、再上传。
3. 制作机应在同步后看到缩略图和模板数量。点击「制作」使用本地完整原图。
   两端原图可以用 `Get-FileHash -Algorithm SHA256` 核对。
4. 在制作机导出有订单关联的成品，客服机同步接收。测试断网重启、暂停后重试。
   设置页可查看待处理任务并打开 `data/qiniu-sync.log` 所在目录。

首版默认文件上限为 100 MiB，原图来源不明或仅取到缩略图的排单保留本地。
只同步启用七牛之后创建的素材，旧订单和原文件继续留在各自原位置。
已接入的目录关掉七牛并重启后进入本地模式。切换新的业务空间使用单独的
EXE 和 `data/` 目录。制作端同步同一业务空间时，模板图片来自 EXE，
两端需要使用匹配的模板版本。
